# Spec-Driven Development (SDD) - Prototipe Aplikasi "Setara"

## 1. Ringkasan Proyek (Project Overview)
**Nama Proyek:** Setara (Platform Penghubung Teman Tuli & JBI)
**Fase:** MVP / Prototipe 
**Area Uji Coba (Pilot):** Surabaya
**Tujuan Utama:** Membangun platform *on-demand* berbasis lokasi (*Online-to-Offline*) yang menghubungkan Teman Tuli dengan Juru Bahasa Isyarat (JBI) terdekat untuk pendampingan langsung.
**Pengembangan Lanjutan:** Komunikasi jarak jauh melalui panggilan video (*real-time lisan ke isyarat*).

---

## 2. Spesifikasi Teknologi (Tech Stack)
* **Environment & IDE:** VSCode
* **Frontend:** Next.js (React) dengan Tailwind CSS (desain antarmuka *sleek* & responsif).
* **Backend & Database:** Supabase (Autentikasi, Realtime Subscriptions) dengan ekstensi PostGIS untuk infrastruktur *database* spasial.
* **Mapping & Geolocation:** Google Maps API / Mapbox GL JS dan Geolocation API peramban (*browser*).
* **Video Communication (Fase Lanjut):** WebRTC terintegrasi (Agora / Twilio).
* **Version Control:** GitHub untuk manajemen *repository*.
* **Deployment:** Vercel untuk mengelola *production deployment* aplikasi *web*.
* **AI Programming Assistant:** Kiro (ditugaskan khusus untuk mengoptimasi implementasi kode *matchmaking algorithm* spasial dan pelacakan status).

---

## 3. Fitur Inti MVP (Prioritas Offline-First)

### A. Sisi Pengguna (Teman Tuli)
1.  **Sistem Autentikasi:** Login/Register sederhana terintegrasi Supabase Auth.
2.  **Peta & Titik Jemput:** Antarmuka peta interaktif yang mendeteksi lokasi pengguna saat ini (*current location*) untuk menetapkan titik pertemuan.
3.  **Order Matching:** Tombol "Cari JBI" yang mencari JBI dalam radius tertentu (misal: 10 KM).
4.  **Live Tracker:** Tampilan status pemesanan (Mencari -> Menuju Lokasi -> Tiba -> Sesi Berlangsung -> Selesai).

### B. Sisi Mitra (JBI)
1.  **Toggle Ketersediaan Offline:** Tombol *switch* status (Tersedia / Sibuk / Offline) yang memperbarui titik koordinat lokasi JBI secara langsung ke *database*.
2.  **Notifikasi Penugasan:** *Pop-up* menerima/menolak permintaan pendampingan, lengkap dengan estimasi jarak dan titik temu.
3.  **Navigasi:** Tombol pintasan untuk membuka rute perjalanan di aplikasi pihak ketiga (Google Maps).
4.  **Konfirmasi Kehadiran:** Tombol "Saya Sudah Tiba" dan "Selesaikan Sesi".

---

## 4. Alur Pengguna (User Journey - Offline Matchmaking)

1.  **Inisiasi:** Pengguna membuka aplikasi, memberikan izin lokasi, dan menggeser *pin* pada peta ke titik temu yang diinginkan (contoh: lobi hotel atau restoran di Surabaya).
2.  **Pencarian:** Pengguna melengkapi patokan alamat dan menekan "Cari JBI". Aplikasi memanggil fungsi spasial dari Supabase PostGIS.
3.  **Penerimaan:** JBI terdekat menerima notifikasi. Jika JBI menekan "Terima", status berubah menjadi `heading_to_location`.
4.  **Pelacakan:** Pengguna melihat estimasi kedatangan. JBI memperbarui status menjadi `arrived` saat sampai di lokasi.
5.  **Eksekusi:** Sesi pendampingan tatap muka (*in-person*) berjalan.
6.  **Penyelesaian:** JBI menekan "Selesaikan Sesi", aplikasi mencatat durasi penyelesaian di sistem.

## 5. Struktur Database (Supabase PostgreSQL + PostGIS)

### Tabel: `users`
* `id` (UUID, Primary Key)
* `role` (String: 'deaf_user' | 'jbi')
* `full_name` (String)

### Tabel: `jbi_profiles`
* `user_id` (UUID, Foreign Key ke `users`)
* `offline_available` (Boolean, Default: false)
* `current_location` (Geometry Point 4326, via PostGIS)
* `specialty` (String)

### Tabel: `offline_bookings`
* `id` (UUID, Primary Key)
* `user_id` (UUID, FK)
* `jbi_id` (UUID, FK)
* `meeting_point` (Geometry Point 4326, via PostGIS)
* `address_detail` (Text)
* `status` (Enum: 'searching', 'heading_to_location', 'arrived', 'in_progress', 'completed')
* `created_at` (Timestamp)

## 6. Fase Pengembangan (Development Roadmap)

### Fase 1: Infrastruktur & Autentikasi (Minggu 1)
* Inisialisasi *repository* kode di GitHub.
* Setup *project* Next.js dan Supabase.
* Pembuatan skema *database*, mengaktifkan ekstensi PostGIS, dan konfigurasi RLS (*Row Level Security*).
* Membangun UI Login/Register dan *routing*.

### Fase 2: Peta & Titik Koordinat (Minggu 2)
* Integrasi Maps API di *frontend*.
* Membangun mekanisme tangkapan *latitude* dan *longitude* dari perangkat JBI (*background location update* sederhana) saat status *toggle* diaktifkan.

### Fase 3: Logika Matchmaking Spasial (Minggu 3)
* Menggunakan asisten AI Kiro untuk menulis *Stored Procedure* di PostgreSQL yang menghitung jarak dan mencari JBI terdekat (berdasarkan *current_location* di tabel `jbi_profiles`).
* Mengintegrasikan UI pemesanan dari sisi pengguna.

### Fase 4: Realtime Tracker & Deployment (Minggu 4)
* Implementasi Supabase Realtime agar layar pengguna dan JBI tersinkronisasi saat ada perubahan status pemesanan.
* Proses *deployment* ke Vercel dan uji coba fungsional lapangan.

### Fase 5: Modul Video Call (Roadmap Lanjutan)
* Penambahan tabel `call_logs`.
* Integrasi WebRTC untuk sesi terjemahan virtual dari lisan ke isyarat (tanpa harus bertemu secara fisik).
